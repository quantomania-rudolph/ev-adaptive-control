# ev-powertrain-sim: Tier 1 plant (GEM PMSM + saturation ledger)

Reproduces the notes' Experiments A to D on a real PMSM drive and logs every request-vs-delivered gap.

## Setup (pinned: these exact versions were tested on Python 3.13)
    python -m venv env && env/bin/pip install -r requirements.txt

## Run
    python run_exp.py --name A --mode naive                       # no saturation
    python run_exp.py --name B --mode naive  --event              # naive adaptive + sudden 25 V ceiling
    python run_exp.py --name C --mode robust --event              # sigma-mod + projection
    python run_exp.py --name D --mode aw     --event              # anti-windup (e_a = e - z)
    python run_exp.py --name Dg --mode aw --event --governor      # + current-feasibility governor
    python analyze.py && python plot_abcd.py && python plot_governor.py
    pytest -q tests/

One run = 8 s simulated = 80,000 steps = about 45 s of wall time on 1 core. Outputs: `runs/<name>.parquet`
(one row per 100 microsecond step, ledger + controller internals + V(t)) and `runs/<name>.json` (manifest).

## Files
- `plant.py`: GEM adapter. Our own disc saturation, zero-sequence injection, time-varying road load, ledger rows M2/M3.
- `control.py`: cascade controller. Adaptive q-axis loop (naive / robust / aw), speed PI, optional governor.
- `run_exp.py`: scenario and logging. `analyze.py`: summary table. `plot_*.py`: figures.
- `tests/test_plant.py`: pins the GEM behaviours this project depends on.

## Measured facts about GEM 3.0.3 this code depends on
1. Action = 3 phase duty cycles in [-1, 1], not (u_d, u_q). Out-of-range actions are clipped silently.
2. Per-leg clipping makes the saturation region direction dependent in dq. We project onto a disc of radius
   V_dc/sqrt(3) (173.2 V at 300 V) after zero-sequence injection, so GEM never clips (M3 = 0 in all runs).
3. Episode terminates when sqrt(i_d^2 + i_q^2) exceeds the current limit unless `constraints=()` is passed.
4. Default load is constant-speed. `RoadLoad` subclasses PolynomialStaticLoad (mechanical_ode receives t).
5. Open-loop d/q currents match the textbook equations to 1e-10 A; torque matches 1.5 p (psi + (Ld - Lq) i_d) i_q.
6. About 5,800 raw steps/s, about 3,900 steps/s with the controller. Reruns are bit-identical.
7. NumPy 2: `np.cross` on 2-vectors no longer works (found by a test).

## Data product (new)
- `telemetry.py`: `CATALOG` (75 channels: name, unit, group, role, meaning) and `derive()` which adds the f/g/d split, power and energy ledgers, and validation residuals to any run log.
- `viewer/build_viewer.py` + `viewer/data_viewer.html`: self-contained page that plots every channel for runs B and Dg.
- Sign convention: delta = delivered - requested. Prefer `dP_mech` / `E_mech_unserved` for energy mismatch; the electrical `E_unserved` is a counterfactual and can be negative.

## Battery + DC link (new)
- `battery.py`: pack (OCV(SOC), R0(T), RC branch, BMS current limits, thermal state) -> busbar -> DC-link capacitor. V_dc is now a state; the inverter ceiling is V_dc/sqrt(3).
- Run: `python run_exp.py --name Eb --mode naive --event --battery` (event = BMS derate to 5 A for 1 s) and `--name Eg --mode aw --event --battery --governor --vdc-aware`.
- New mismatch rows: M9 `bus_sag`, `ceiling_loss`; M10 `d_i_dc` (pack delivered minus inverter requested), `E_bus_unserved`.
- ASSUMPTIONS (generic NMC numbers, not a real pack): OCV table, R0/R1/tau, BMS limits, inverter loss, thermal mass.
- Known limitation: ceiling is capped at 173.2 V (GEM's 300 V scale) so regen overshoot above 300 V cannot give extra headroom.

## Real drive cycles (new)
- `cycles.py`: loader and sanitiser for any speed-vs-time file (TUM Tesla Model 3 CAN traces, EPA UDDS, plain CSV), the
  `VehicleEq` mapping (reflects mass, drag, rolling, grade onto the motor shaft) and `fit_vehicle_to_motor`. Every repair is a
  FIX, WARN or named ERROR in a saved report; nothing is changed silently. 51 tests in `tests/test_cycles.py`
  (set `TUM_DIR` to run the real-track tests; they skip if the files are absent).
- `run_cycle.py`: runs a cycle through motor + controller + battery + DC link, optionally with a BMS cut at peak power.
      python run_cycle.py --source tum:track_0.csv --name T0n --mode naive --battery --derate
      python run_cycle.py --source tum:track_0.csv --name T0p --mode aw --governor --vdc-aware --battery --derate
- Dataset: Rosenberger et al., TUM, "Electric powertrain data of a Tesla Model 3 during real-world driving situations",
  doi:10.14459/2024mp1735471, CC BY 4.0. Only tracks 0, 1, 10, 100, 103 were downloaded (checksum-verified). Highway tracks need
  `--allow-road-scale`. Findings: sim battery power correlates 0.65 with the real car at 5 s smoothing; regen share 12% vs 38%.

## Dashboard (new)
    python dashboard/build_dashboard.py      # needs runs/{A,B,C,D,Dg,Eb,Eg,T0n,T0p}.parquet + .json
    python dashboard/audit_data.py           # every number on the page vs the raw parquet files
    python dashboard/audit_ui.py             # headless-browser stress test (needs playwright)
`dashboard/dashboard.html` is one self-contained file: powertrain map with live per-stage data and blurbs, a runaway plot that
fills in on playback, bounded-state checks, battery and DC-link plots, mismatch ledger and a searchable channel catalog.
Bounded-state results are evidence from simulation, not a stability proof.

Note: `data/runs_all_downsampled/` holds every run used by the dashboard, thinned for size (7 plain runs at 500 Hz, the two
real-drive runs at 20 Hz). Full-rate files are regenerated with `run_exp.py` and `run_cycle.py`.

## Electrical mismatch, data attribution, bounds and the mismatch map (new)
- `docs/ELECTRICAL_MISMATCH.md`: why the shaft-power gap is not the electrical gap, and the exact rebuild
  `dP_elec_ref = dP_mech + dP_cu + P_mag`. Three electrical requests (reference-implied, actuator, voltage-command) and what each is for.
  New channels in `telemetry.CATALOG`: `P_req_ref`, `dP_cu`, `dP_elec_ref`, `E_elec_ref_unserved`, `P_that`, `P_psi_err`, `P_fb`, `resid_*`.
- Disturbance vector (shaft torque, N.m): `T_roll`, `T_visc`, `T_aero` (sum to `T_fric`) and `T_dist` (grade and any injected torque); the speed
  reference is `omega_ref`. `docs/DATASET_INVENTORY.md` lists which real columns fill each term and which need assumptions.
- `cycles.data_demand` and the logged columns `T_req_data`, `T_avail`, `data_ratio`, `data_infeasible`: what the DATA asks of the motor before any
  controller. Where `data_ratio > 1` no controller could comply, so mismatch there belongs to the data. Mismatch elsewhere belongs to the
  controller, the plant or an injected fault.
- `bounds.py`: bounded input (checked, true by construction), peak and ultimate bounds, settle time, descriptive decay fit of V.
  Measurements of one run, not proofs.
- `run_classes.py` runs naive, protected and protected-no-fault controllers on synthetic ramp, sine and step requests and on real urban
  (UDDS), mixed, suburban and highway (road-scaled) drives. `mismatch_map.py` turns every run into `data/mismatch_map.csv/json`.
- Logging note: cycle runs log every 5 ms. `derive()` now reads the row spacing from the time axis and flags
  `df.attrs["derivative_channels_valid"] = False` when rows are too coarse for the derivative channels (`P_mag`, `resid_*`). The pointwise
  mismatch rows (M1 to M6d, M9, M10) stay exact at any rate.
- Tests: `tests/test_bounds.py` (28), `tests/test_pipeline.py` (written by an independent reviewer from a spec; it found three real defects, now fixed or documented).
